# 世界书卡面管理 / Worldbook Gallery

> 一个 SillyTavern 扩展。把世界书按「它绑定哪张角色卡」铺开显示，每本世界书贴着那张卡的卡面。
> 角色卡一多、世界书认不出来的时候，看一眼卡面就知道是哪本。

A SillyTavern extension that displays your World Info / Lorebooks as a gallery of character card covers — so you can tell which lorebook belongs to which card at a glance.

---

## 它解决什么问题

导入的角色卡多了，世界书也跟着变多。角色卡好认——有名字、有卡面图案；
但世界书名字有的跟卡一样，有的很奇怪，隔一段时间回去玩就分不清哪本是哪张卡的。

这个扩展把**每本世界书对应的角色卡卡面**直接贴在它上面。
看到图，就知道是哪本。

---

## 只读，不改任何东西（除了你自己拨的开关）

这一点是设计红线：

- **不写任何文件。** 扩展只读取「有哪些世界书」「有哪些卡」，然后展示。
- **不改任何名字。** 世界书和角色卡在磁盘上的文件名一个字都不动。
  面板里看到的名字是运行时拼出来的，关掉就没了。
- **不改卡片内容。** 不往角色卡里写任何数据。
- **点一下只是打开查看。** 点击格子会调起酒馆自带的世界书编辑器，你不操作它什么都不改。
- **唯一的例外是卡片上的开关。** 开关控制的是「世界书当前开没开」，
  改的是酒馆设置里的那份启用列表——和你自己在酒馆界面里勾选／取消勾选是**同一件事**，
  不涉及任何文件读写。

删掉扩展文件夹即完全恢复原状，不留任何残留。

---

## 启用状态与开关

面板里每本世界书的卡片左下角有一个状态标（**已开启** / **已关闭**），
下方有一个开关按钮，可以直接拨。

**它和酒馆自己界面是同一份状态，双向同步：**

- 你在酒馆界面里勾选了某本世界书 → 面板里这张卡片立刻变成「已开启」（绿边亮起）。
- 你在面板里拨开关 → 酒馆那份启用列表也跟着变，酒馆还会自己弹一句「已开启：xxx」。

顶部统计行会显示当前一共开了几本。工具栏上还有 **「只看已开启」**，
勾上之后网格里只剩正在生效的世界书，方便确认「到底哪些在起作用」。

> 这解决的就是「我不知道世界书有没有生效」这个问题——现在看一眼卡片就清楚了。

---

## 原理

对应关系的来源是**角色卡自身的绑定字段**：

```
character.data.extensions.world
```

每张角色卡的 PNG 里都记录了它绑定的是哪本世界书。读取这个字段，
就能**准确地**（而不是靠名字猜）把卡面配给世界书。

另外还会读取 `character.data.character_book`，识别出**卡片自带但尚未导入**的世界书。

> 参考：SillyTavern `public/scripts/world-info.js` 第 1127、4164、5567、6205 行附近。

## 安装

### 方式一：从 Git URL 安装（推荐）

酒馆里点 **扩展** → **安装扩展** → 填入本仓库地址，然后点「只给我安装」：

```
https://github.com/cccscccc/sillytavern-visual-worldbook
```

装好后**刷新酒馆页面**。

### 方式二：手动放置

把整个文件夹放到：

```
<SillyTavern>/public/scripts/extensions/third-party/worldbook-gallery
```

### 方式三：用附带的脚本（Windows）

```powershell
.\install.ps1 -Action install      # 安装
.\install.ps1 -Action update       # 更新（会先备份旧版）
.\install.ps1 -Action uninstall    # 卸载
.\install.ps1 -Action status       # 查看装没装
```

脚本会自动寻找酒馆目录；找不到时手动指定：

```powershell
.\install.ps1 -Action install -TavernRoot "D:\SillyTavern"
```

## 使用

1. 点酒馆右上角的**扩展设置**（插头图标）。
2. 找到 **「世界书卡面管理」**，展开。
3. 点 **「打开卡面面板」**。

右侧滑出面板，世界书按卡面铺开。

### 面板说明

| 元素 | 含义 |
|---|---|
| 上方图片 | 绑定这本世界书的角色卡卡面 |
| 左下角状态标 | **已开启** / **已关闭** |
| 粗体文字 | 展示名，默认「卡名 · 世界书名」 |
| 小字 | 条目数，以及世界书的真实文件名 |
| 右上角「N 张卡」 | 多张卡共用这本世界书 |
| 下方开关 | 点一下开启／停用，和酒馆界面同步 |

### 视觉上的区分

- **绿边、亮起来、状态标写着「已开启」** —— 这本正在生效。
- **压暗、状态标写着「已关闭」** —— 这本没生效。

### 三种特殊状态会被标出

- **灰色虚线框** —— 这本世界书没有任何卡在用（孤立条目，通常可清理）。
- **橙色边框，提示「卡里写了，但世界书文件不存在」** —— 有卡指名要用它，但文件没了。
  这种情况进游戏会出问题。
- **图片位置显示文件图标** —— 没有卡绑定，因此无卡面可显示。

### 工具栏

- **搜索框** —— 按卡名或世界书名过滤。
- **显示风格** —— 「卡名 · 世界书名」/「只显示卡名」/「只显示世界书名」。
- **显示未绑定的世界书** —— 取消勾选可隐藏孤立条目。
- **只看已开启** —— 只显示当前正在生效的世界书。
- **重新扫描** —— 导入新内容后手动刷新。

## 配对准确度

取决于角色卡是怎么进入酒馆的：

| 导入方式 | 配对效果 |
|---|---|
| **整卡导入**（世界书随卡一起来） | **准确**。卡自身记录着绑定关系，不靠猜。 |
| 卡与世界书分开单独导入 | 部分无法配对，会显示为「未绑定卡」。 |

推荐使用整卡导入。

## 自检

仓库内附带不依赖浏览器的自检脚本：

```bash
node _selftest.mjs              # 配对逻辑，15 项
node _selftest_toggle.mjs       # 开关逻辑，43 项
node _verify_load.mjs           # 真加载模拟（验证能装能跑）
node _verify_ps1_encoding.mjs   # PowerShell 脚本编码，10 项
node _verify_api.mjs            # 核对用到的酒馆符号真实存在，11 个
```

- `_selftest.mjs` 覆盖配对逻辑的 15 项断言（正常绑定、重名导入产生的后缀、
  孤立世界书、缺失世界书、卡片自带世界书、三种展示名风格等）。
- `_selftest_toggle.mjs` 覆盖开关逻辑的 43 项断言（读状态、开、关、
  不重复操作、显式指定、名字含逗号的兜底、失败时不假装成功、空名字、
  **借酒馆 change 通道回写是否真的同步到 `globalSelect`**、
  **下拉框里没这本书时不能误清空状态**、**下拉框还是空的时候要先热身**等）。
- `_verify_load.mjs` 会造一棵假的酒馆目录树真 `import()` 一次，
  确认扩展能加载、hook 存在、`init` 能跑起来。
- `_verify_ps1_encoding.mjs` 确认 `install.ps1` 有 UTF-8 BOM（没有的话
  Windows PowerShell 5.1 会把中文当 GBK 读，脚本直接跑不起来）。
- `_verify_api.mjs` 逐个核对本扩展从酒馆源码里导入的每个符号是否真实存在
  （用 `TAVERN_ROOT=/path/to/SillyTavern node _verify_api.mjs` 指定酒馆目录）。
  导入一个不存在的符号会让整个扩展加载失败，所以这项必须在真酒馆目录上跑一次。

## 已知限制

- 世界书名里如果**含逗号**，面板的开关会绕开酒馆的斜杠命令通道，
  改用直接操作界面下拉框的方式。功能一致，但如果哪次不生效，
  可以看浏览器控制台里的日志（前缀 `[Worldbook Gallery]`）。
- 开关只控制**全局启用**列表。酒馆还有「按角色卡绑定」「按聊天绑定」两套独立机制，
  本扩展不干预那两套。
- 若酒馆的世界书面板从未打开过，本扩展会先自动刷新一次世界书列表
  （等价于帮你把面板打开一下），再执行开关。这一步只重画列表，不改内容、不写文件。
